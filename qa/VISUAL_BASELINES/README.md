# Visual baselines

Approved reference screenshots for critical screens (Addendum §4.3, §18-6). 14 images: dashboard, POS, orders, receivables, events, accounting setup, profit × desktop (1440×900) and mobile (390×844). File name: `{screen}-{viewport}-chrome-desktop.png`.

## How they were produced
Created with `PW_CHANNEL=chrome npx playwright test tests/e2e/a11y-visual.spec.ts --update-snapshots` against the production build with a pinned clock and the deterministic demo seed, then **re-run unchanged and passed** (stability check). Tolerance: 1 % of pixels (`maxDiffPixelRatio`), animations disabled.

## Limits — read before trusting a pass
- Rendered by **Google Chrome on Windows 11** with this machine's fonts and text rendering. The same build on macOS/Linux/another Chrome version will differ slightly; regenerate baselines per CI environment.
- Only these 14 screens/viewports. Other screens are covered by the structural responsive and accessibility suites, not by pixel comparison.
- Dark theme and the customer app are covered by axe, not by screenshots.
- **Approval:** the baselines were generated by the implementation agent and visually spot-checked (one image opened). They have **not been approved by a product/design owner** — treat them as "no unintended change" detectors, not as approved designs.

## Updating
1. Run the suite; open the diff images in `test-results/`.
2. If the change is intended, run with `--update-snapshots`, review every changed image, commit images and the reason together.
3. Never update baselines to make a red run green without understanding the diff.
