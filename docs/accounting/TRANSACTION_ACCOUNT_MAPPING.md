# Transaction → Account Mapping

Version 1.0 · Addendum §23.5, §23.13. Machine-readable version: `TRANSACTION_ACCOUNT_MAPPING.csv` (generated from the live configuration by `scripts/gen-accounting-docs.ts`). **Mapping is a proposal until approved by a qualified accountant.**

Business logic never names an account. It posts to **posting roles**; the mapping (versioned, effective-dated, four-eyes) resolves a role to an account when the journal is created. If a role has no valid mapping, the transaction is **blocked** (exception), never posted elsewhere.

## 3. Observed gaps against §23.5
- No work-in-process account/stage (production moves raw materials to finished goods).
- Loyalty-points liability, deferred revenue for prepaid/stored value and platform-funded discounts are not posted (see `ACCOUNTING_POLICY_REGISTER.md` POL-11, POL-14, POL-21).
- Non-creditable input VAT is defined as a tax code but not applied by posting rules (POL-16).
- Fixed assets, depreciation, payroll, withholding tax: not implemented.

## 4. Change control
Mapping change = proposal (role, new account, **effective-from date**, reason) → approval by a different user → audit entry. Earlier postings are never rewritten; a change inside a closed period is refused; direct edits are refused after setup approval. Evidence required with every change: ACC suite result + reconciliation matrix (`ACCOUNTING_RECONCILIATION_MATRIX.md`).
