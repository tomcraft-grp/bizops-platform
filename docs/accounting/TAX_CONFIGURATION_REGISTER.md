# Tax Configuration Register

Version 1.0 · Addendum §23.9, §23.13. Tax codes are **data**, not code: rates live in the effective-dated tax register and are looked up by transaction date. **The values below are demo defaults. A qualified Thai accountant must confirm rates, treatment, registration status and any special periods before use.** Nothing here is tax advice.

## 2. Rules implemented
| Rule | Behaviour | Test |
|---|---|---|
| Effective dating | A new rate is a new **version** with `effectiveFrom`; lookup uses the transaction date; historic documents keep their stored snapshot | `a new rate version applies only from its effective date; history keeps its own snapshot` |
| Sale snapshot | Each order stores tax code, rate, base, amount and rule version | `a sale stores tax code, rate, base, amount and rule version` |
| Tax-inclusive pricing | Default on: price includes VAT; base and VAT are split to the satang, journal still balances | pricing boundary tests (8 price points) |
| Not VAT-registered | Profile flag off → no output VAT is posted | `a business that is not VAT-registered posts no output VAT` |
| Output VAT / input VAT | Output in *Output VAT* (liability), creditable input in *Input VAT* (asset); returns reverse output VAT | `VAT report: output − input, and a return reverses output VAT` |
| Expenses | The VAT amount entered on an expense is posted to *Input VAT*. **Gap:** the non-creditable code (`VAT7NC`) is defined in the register but the posting rules do not yet capitalise such VAT into the expense | `expenses must use an expense account and keep VAT in input VAT` |
| VAT control reconciliation | VAT GL balance = tax base of sales, purchases and expenses | reconciliation matrix row *VAT (output − input)* |
| Change control | Tax code changes need `accounting:create`; the setup page flags tax-version history; changes are audited | `authz.test.ts`, setup checks |

## 3. Not implemented — decide with the accountant
Withholding tax (WHT) rates and certificates, PND forms, PP.30 return layout, e-Tax invoice / e-receipt formats and tax-invoice numbering rules, abbreviated tax invoices for POS, special/reduced VAT rate periods, specific business tax, stamp duty. The prototype produces a VAT *summary* report only (output − input by period); it is **not** a filing format.
